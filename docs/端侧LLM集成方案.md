## 第一部分：你需要了解的概念

### 1. 端侧 LLM 是什么？

**端侧 LLM** = 在用户的手机/电脑上本地运行大语言模型，而不是调用 ChatGPT/Claude 的云端 API。

```
云端 LLM（你熟悉的）：                    端侧 LLM（新的）：
┌──────────────┐                       ┌──────────────────┐
│   你的 App   │──HTTP请求──►│  OpenAI服务器   │
│  (Flutter)   │◄──JSON────│  (GPU集群)      │
└──────────────┘                       └──────────────────┘
     需要联网                              模型在手机上
     按 token 收费                          完全离线
     数据发出去                              隐私安全

端侧 LLM 的架构：
┌─────────────────────────────────────────────┐
│                你的手机                       │
│  ┌──────────────┐  ┌──────────────────────┐ │
│  │  Flutter App │  │   本地 LLM 模型文件   │ │
│  │  (UI + 逻辑) │  │   (几个GB的权重文件)  │ │
│  └──────┬───────┘  └──────────┬───────────┘ │
│         │                      │              │
│         └───────加载/推理──────┘              │
│                (本地计算，无需网络)             │
└─────────────────────────────────────────────┘
```

**为什么端侧 LLM 现在可行了？**

以前不行，现在可以了，因为两个突破：

1. **模型变小变强了**：以前最小也要 70B（700亿参数），现在 3B（30亿参数）的模型就能做很多事了
2. **量化技术**：把模型从 32 位浮点数压缩到 4 位整数，体积缩小 8 倍，精度损失很小

```
原始模型：Qwen 2.5 3B（32位浮点）
  └── 大小：约 12 GB
  └── 手机装不下

量化后：Qwen 2.5 3B INT4（4位整数）
  └── 大小：约 1.8 GB
  └── 速度：手机上每秒输出 20-40 个 token（中文约 10-20 个字/秒）
  └── 完全可用！
```

### 2. llama.cpp 是什么？

**一句话：llama.cpp 是一个用 C++ 写的程序，专门用来在各种设备上运行大语言模型。**

```
llama.cpp 的定位：

┌─────────────────────────────────────────────────────────┐
│  想象你有一个 .mp3 音乐文件                              │
│                                                         │
│  .mp3 文件 ──► 音乐播放器（如网易云音乐）──► 听到声音     │
│                                                         │
│  同理：                                                  │
│  模型文件 ──► llama.cpp ──► 生成文本                    │
│                                                         │
│  llama.cpp 就是"模型播放器"                              │
└─────────────────────────────────────────────────────────┘
```

**llama.cpp 的特点**：
- **纯 C++**：没有依赖，编译成二进制就能跑
- **跨平台**：Android、iOS、Windows、macOS、Linux、甚至树莓派都能跑
- **支持几乎所有开源模型**：Llama、Qwen、ChatGLM、Phi、Gemma、Mistral...
- **自动利用硬件加速**：CPU 多线程、GPU（Vulkan/Metal/CUDA）、甚至手机 NPU
- **社区最活跃**：端侧 LLM 的事实标准，几乎所有端侧 AI App 都在用它

**你不需要深入理解 llama.cpp 的内部原理**，就像你用 FFmpeg 处理视频不需要理解 H.264 编码细节一样。你只需要知道如何"调用"它。

### 3. FFI 是什么？

**FFI = Foreign Function Interface（外部函数接口）**

**一句话：FFI 让 Dart 代码直接调用 C/C++ 写的函数。**

```
为什么需要 FFI？

┌─────────────────────────────────────────────┐
│                                             │
│  Dart 不擅长的事情：                           │
│  • 矩阵运算（慢 50-100 倍）                   │
│  • 直接操作 GPU                              │
│  • 管理 GB 级别内存                          │
│                                             │
│  C/C++ 擅长的事情：                           │
│  • llama.cpp 就是 C++ 写的                   │
│  • 矩阵运算极快                              │
│  • 直接调用 GPU 驱动                         │
│                                             │
│  FFI 就是连接两者的桥梁：                      │
│                                             │
│     Dart 代码 ──FFI──► C++ 函数              │
│     "帮我加载模型"     "好的，加载中..."       │
│     "生成下一句"       "生成结果是：xxx"       │
│                                             │
└─────────────────────────────────────────────┘
```

**FFI 在 Flutter 中的代码长什么样？**

```dart
// Dart 代码通过 FFI 调用 C 函数

// 1. 加载 C 库（Android 上是 .so 文件）
final lib = DynamicLibrary.open('libllama.so');

// 2. 找到 C 函数并包装成 Dart 函数
final generate = lib.lookupFunction<
  Pointer<Utf8> Function(Pointer<Utf8> prompt),  // C 侧签名
  Pointer<Utf8> Function(Pointer<Utf8> prompt)   // Dart 侧签名
>('llama_generate');

// 3. 像调用普通 Dart 函数一样调用
final result = generate("你好".toNativeUtf8());
print(result.toDartString());  // 输出："你好！有什么我可以帮你的吗？"
```

**类比**：就像你在 Android 里用 JNI 调用 C++ 代码，FFI 是 Dart 版本的 JNI。

### 4. MLC / MLC Chat 是什么？

**MLC = Machine Learning Compilation（机器学习编译）**

**一句话：MLC 是一套工具链，把大模型"编译"成针对特定设备优化过的代码。**

```
llama.cpp vs MLC 的区别：

┌──────────────────────────────────────────────────────────┐
│                                                          │
│  llama.cpp（解释执行模式）                                 │
│  ───────────────────────                                  │
│  模型文件（GGUF）──► llama.cpp 读取并解析 ──► 逐层计算    │
│                                                          │
│  就像：Java 字节码 ──► JVM 解释执行                       │
│                                                          │
│  优点：通用性强，任何模型都能跑                             │
│  缺点：每次运行都要解析模型结构，启动稍慢                    │
│                                                          │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  MLC（编译执行模式）                                       │
│  ─────────────────                                        │
│  模型文件（原始）──► MLC 编译器 ──► 优化后的部署包           │
│                                     ├── .so（计算库）      │
│                                     └── params（权重文件）  │
│                                                          │
│  编译时做的优化：                                          │
│  • 针对特定 GPU/NPU 生成最优算子                           │
│  • 内存访问模式优化                                       │
│  • 算子融合（减少数据传输）                                │
│                                                          │
│  就像：C 代码 ──► GCC 编译成机器码 ──► 直接执行            │
│                                                          │
│  优点：推理速度通常更快，内存管理更好                        │
│  缺点：模型需要预编译，换模型要重新编译，灵活性差              │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**MLC Chat**：MLC 项目提供的一个聊天 App 示例，有 Android/iOS/Web 版本。

### 5. GGUF 是什么？

**GGUF = GPT-Generated Unified Format**

**一句话：GGUF 是一种专门为大模型设计的文件格式，llama.cpp 用它。**

```
模型格式的演变：

PyTorch 格式（训练时用）         HuggingFace 格式（发布时用）
┌──────────────┐                ┌──────────────┐
│ model.pt     │                │ config.json  │
│ 大，慢        │                │ model.safetensors│
│ 不适合部署    │                │ 多个文件      │
└──────────────┘                └──────────────┘
                                       │
                                       ▼
                                GGUF 格式（端侧部署用）
                                ┌──────────────┐
                                │ model.gguf   │
                                │ 单文件       │
                                │ 已量化       │
                                │ llama.cpp   │
                                │ 直接加载     │
                                └──────────────┘
```

**GGUF 的特点**：
- **单文件**：一个 .gguf 文件包含所有信息（配置、词表、权重）
- **已量化**：内置 INT4/INT8/FP16 等量化权重
- **即插即用**：下载下来就能被 llama.cpp 加载

**类比**：.gguf 就像 .apk，是一个打包好的、可以直接运行的格式。

### 6. 量化（Quantization）是什么？

**一句话：量化是把模型参数从大数变成小数，让模型文件更小、运行更快。**

```
量化原理（简化版）：

原始模型权重（32位浮点数）：
┌────────────────────────────────────────┐
│ 0.0034567890                           │
│ 占 4 个字节                             │
│ 精度很高                                │
└────────────────────────────────────────┘
           │
           ▼ 量化

量化后（4位整数）：
┌────────────────────────────────────────┐
│ 用 4 个 bit 表示相对大小                 │
│ 占 0.5 个字节                           │
│ 精度降低，但够用                          │
└────────────────────────────────────────┘

效果对比（以 Qwen 2.5 3B 为例）：
┌──────────────┬──────────┬──────────┬─────────────┐
│   格式       │ 文件大小  │ 内存占用  │ 质量损失     │
├──────────────┼──────────┼──────────┼─────────────┤
│ FP16 (16位)  │  6 GB    │  6 GB    │  0% (基准)   │
│ INT8 (8位)   │  3.5 GB  │  3.5 GB  │  ~1%        │
│ INT4 (4位)   │  1.8 GB  │  2 GB    │  ~3-5%      │
│ Q4_K_M       │  1.9 GB  │  2.2 GB  │  ~2%        │
└──────────────┴──────────┴──────────┴─────────────┘

Q4_K_M 是一种更聪明的量化方法，损失更小。
对聊天场景来说，INT4/Q4_K_M 的质量完全够用。
```

### 推荐方案：llama.cpp + FFI 自封装

**核心思路**：基于 llama.cpp 的 C API，自己写 Dart FFI 绑定。社区包（如 `llama_cpp_dart`）可作为参考，但生产级需要自己维护，确保各平台库版本可控。

> 为什么不直接用现成插件？pub.dev 上的端侧 LLM 包目前均处于实验阶段，维护状态不稳定。自己封装 FFI 绑定开发量不大，却能换来完全的控制权。

```
架构图：

┌─────────────────────────────────────────────────────────────┐
│                    Flutter 层 (Dart)                         │
│                                                             │
│   ┌─────────────┐    ┌─────────────┐                       │
│   │  Chat UI    │◄──►│  ChatService│                       │
│   │  (Flutter)  │    │  (Dart)     │                       │
│   └─────────────┘    └──────┬──────┘                       │
│                             │                               │
│                    ┌────────▼────────┐                      │
│                    │  Dart FFI 绑定层 │  ← 自己维护            │
│                    │  (Dart API)     │     调用 C API         │
│                    └────────┬────────┘                      │
│                             │                               │
└─────────────────────────────┼───────────────────────────────┘
                              │
                    ┌─────────▼──────────┐
                    │   FFI (dart:ffi)   │
                    └─────────┬──────────┘
                              │
                    ┌─────────▼──────────┐
                    │  libllama.so /     │
                    │  llama.framework   │  ← 自己编译各平台库
                    └─────────┬──────────┘
                              │
                    ┌─────────▼──────────┐
                    │    llama.cpp        │  ← C++ 推理引擎
                    │    (C API)          │
                    └─────────┬──────────┘
                              │
                    ┌─────────▼──────────┐
                    │   GGUF 模型文件     │
                    │   (下载到本地)       │
                    └────────────────────┘
```

#### 技术栈

| 层级 | 技术选择 | 说明 |
|-----|---------|------|
| LLM 后端 | llama.cpp | 端侧 LLM 的事实标准 |
| Dart ↔ Native | 手写 FFI 绑定 | 调用 llama.cpp 的 C API |
| 原生库编译 | CMake + NDK / Xcode | 自己编译 Android .so、iOS framework |
| 模型格式 | GGUF | 即插即用 |
| Dart 状态管理 | Riverpod / ChangeNotifier | 按项目现有习惯 |

#### 参考的社区包

自己写 FFI 绑定前，可以参考这些项目：

- **`llama_cpp_dart`**：Dart FFI 绑定的实现思路，可直接参考其代码结构，但注意维护状态不稳定

#### 实现步骤

```
Phase 1：编译原生库（1-2 天）
├── 1.1 拉取 llama.cpp 源码
├── 1.2 编译 Android .so（arm64-v8a、armeabi-v7a）
├── 1.3 验证编译产物可用
└── 1.4 下载测试用的 GGUF 模型（Qwen 2.5 0.5B Q4_0）

Phase 2：Dart FFI 绑定（1-2 天）
├── 2.1 定义 C API 的 Dart 函数签名（加载模型、生成文本、释放资源）
├── 2.2 使用 dart:ffi 加载 .so 并绑定函数
├── 2.3 封装成 Dart 层的 LlamaService（隐藏 FFI 细节）
└── 2.4 写最小 Demo：加载模型 + 生成一句话

Phase 3：聊天功能（2-3 天）
├── 3.1 设计 ChatMessage 数据模型
├── 3.2 实现对话历史拼接（把历史对话格式化成 prompt）
├── 3.3 接入流式生成（字一个个出现）
├── 3.4 写聊天 UI（气泡、输入框、加载状态）
```

#### 优点

| 优点 | 说明 |
|-----|------|
| 完全可控 | 不依赖第三方插件，版本、功能自己说了算 |
| Dart 代码占比高 | 90%+ 代码是 Dart，符合"原生只是壳子" |
| 跨平台 | 一套 Dart 代码，原生库各平台分别编译 |
| 模型选择自由 | 任何 GGUF 模型都能用 |
| 学习价值 | 完整理解 FFI 链路，对后续维护有帮助 |

#### 缺点

| 缺点 | 说明 |
|-----|------|
| 需要写 FFI 绑定 | 比直接 import 包多一两天工作量 |
| 需要编译原生库 | Android 需要 .so，iOS 需要 framework |
| 不是开箱即用 | 相比云端 API，端侧模型需要下载、加载 |

## 第四部分：我的推荐

### 为什么是 llama.cpp + 自封装 FFI

1. **你的项目阶段适合快速验证**：当前目标是跑通"端侧模型 + Flutter 对话"这个最小闭环
2. **自己封装 FFI 开发量可控**：llama.cpp 的 C API 很简洁，核心就 5-6 个函数，一两天就能封装完
3. **模型迭代快**：GGUF 模型即下即用，方便测试不同模型效果
4. **不依赖不稳定的第三方包**：pub.dev 上的端侧 LLM 包都处于早期阶段，自己维护更踏实

### 推荐的实现路径（最小 Demo）

```
Day 1：编译原生库
├── 拉取 llama.cpp 源码
├── 用 NDK 编译 Android arm64-v8a 的 .so
└── 确认编译产物无报错

Day 2：Dart FFI 绑定
├── 定义 C API 的 Dart 函数签名
├── 用 dart:ffi 加载 .so
└── 封装 LlamaService：loadModel() + generate()

Day 3：最小验证
├── 下载 Qwen 2.5 0.5B Q4_0（~350MB）
├── 写最小 Demo：加载模型 + "你好" → 看是否返回中文
└── 调试 FFI 调用链路

Day 4-5：聊天 UI
├── ChatMessage 数据模型
├── 对话历史拼接成 prompt
├── 流式输出（逐字显示）
└── 基础 UI（气泡 + 输入框）
```

### 推荐的模型（红米手机专用）

红米手机内存通常在 4-6GB，留给 App 的可用内存约 1-2GB。推荐两个档位：

#### 档位一：极致轻量（首选）

**Qwen 2.5 0.5B Instruct GGUF (Q4_0 量化)**

| 属性 | 值 |
|-----|---|
| 模型文件 | ~350 MB |
| 内存占用 | ~500 MB（运行时） |
| 速度 | 60-100 tok/s |
| 中文能力 | ⭐⭐ 能用（简单对话、问答） |
